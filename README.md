# Dotfiles

NixOS-based personal dotfiles.

## Layout

| Directory              | Description                                                                                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **nixos/**             | Main part of the repo: a flake-based, full NixOS configuration. Host-agnostic setup with two flakes for two hosts (`nixdesktop`, `nixlaptop`) that share common modules and home configuration. |
| **niri/**              | Config for [niri](https://github.com/YaLTeR/niri), my Wayland compositor of choice.                                                                                                             |
| **mango/**             | Config for [mango](https://github.com/mangowm/mango) (mangowc), a dwl-based Wayland compositor selectable alongside niri in the DMS greeter.                                                    |
| **noctalia/**          | [Noctalia](https://github.com/noctalia-dev/noctalia-shell) shell config used with niri.                                                                                                         |
| **DankMaterialShell/** | [DankMaterialShell](https://github.com/AvengeMedia/DankMaterialShell) shell config used with niri/mango.                                                                                        |
| **julia/**             | Simple Julia startup script enabling [Revise](https://github.com/timholy/Revise.jl) and [OhMyREPL](https://github.com/KristofferC/OhMyREPL.jl).                                                 |
| **[onedrive-sync/](onedrive-sync/README.md)** | Dotfiles to make OneDrive work seamlessly on Linux over WebDAV. Auth tokens are fetched from Firefox; `onedrive-download`/`onedrive-upload` (`.local/bin`) handle sync. See the [usage guide](onedrive-sync/README.md). |
| **neovim/**             | Stowable Neovim config ([nix-wrapper-modules](https://github.com/BirdeeHub/nix-wrapper-modules)): `flake.nix` + lua + `module.nix` under `.config/nvim` (`stow neovim` → `~/.config/nvim`). NixOS takes `neovim/.config/nvim` as the `nvim-config` input and installs via `getInstallModule`. `wrappers.neovim.liveLua` (default `true`) loads Lua from `~/.config/nvim` without rebuilds; set `liveLua = false` to bake the tree into the store. HPC profile: `module-hpc.nix` (trimmed plugins/grammars; Lua skips absent plugins via `config.has`). |
| **HPC Neovim**         | No Nix on the cluster: the `nvim-hpc-bundle` flake output (`neovim/.config/nvim/hpc/bundle.nix`) is one self-contained `nvim-hpc.tar.gz`: official nvim + Quarto releases, the `module-hpc.nix` plugin pack and parsers, the Lua config, static `rg`/`fd`/`stylua`/`shfmt`/`taplo`. Its launcher (`hpc/nvim`) sets `NVIM_APPNAME=nvim-hpc` and links `{~/.config,~/.local/share,~/.local/state}/nvim-hpc` into the bundle, so Neovim's files stay in `nvim-hpc/var` while child processes keep the normal environment; only the disposable cache stays outside, as a plain `~/.cache/nvim-hpc` (e.g. on `$SCRATCH`). The build fails if anything references `/nix/store` or needs glibc > 2.34. `neovim/scripts/nvim-hpc-sync` (fish alias, run on the desktop; `neovim/.stow-local-ignore` keeps `scripts/` out of `~`) builds it from the local Lua tree and installs it next to the cluster's dotdirs (the folder `~/.local` really lives in, never inside `$HOME`; `HPC_PREFIX` to override), keeping `var/` and linking `~/.local/bin/nvim`. SSH uses IPv4 + `~/.ssh/id_jureca` like `mju` (override with `HPC_SSH_OPTS`). LSPs are not shipped; ruff/ty/jupytext/pynvim are uv tools. |
| **emacs/**             | My Doom Emacs configuration, setup for python, julia, and nix development.                                                                                                                      |
| **claude/**            | The whole `~/.claude` folder (`stow claude` → `~/.claude` symlink). `.gitignore` whitelists config only (settings, agents, hooks, themes, `skills/ask`); credentials, transcripts and caches stay local. Includes a read-only **Ask mode**: run `ask` (fish alias) for `claude --agent ask`, with Bash restricted by `hooks/ask-readonly-bash.py`; or `/ask <question>` mid-session. |
| **fish/**              | Fish config (`stow fish` → `~/.config/fish/config.fish`): aliases, Oxocarbon colors, zoxide + starship init. Sources Home Manager's `hm-session-vars.sh` via `babelfish` when present, so it also works on non-NixOS hosts. |
| **starship/**          | [Starship](https://starship.rs) prompt (`stow starship` → `~/.config/starship.toml`): Oxocarbon powerline with OS icon, user, host, directory, git and language segments. |
| **fastfetch/**         | [Fastfetch](https://github.com/fastfetch-cli/fastfetch) config (`stow fastfetch` → `~/.config/fastfetch/config.jsonc`): no logo, boxed key/value columns, one color per section (system, desktop, hardware, miscellaneous). Layout notes are at the top of the file. |
| **bash/**              | Minimal, dependency-free `.bashrc` for HPC (JSC) hosts where bash is mandatory: mirrors `config.fish` aliases, falls back to `xterm-256color` when `$TERM` has no terminfo (e.g. `xterm-ghostty`), detects the host (`jr*`/`jw*`/`jusuf*` or `$SYSTEMNAME`; override with `DOTFILES_PROFILE`) and exports `DOTFILES_PROFILE`. Plain Oxocarbon `PS1` prompt; uses nvim if present, vim/vi otherwise. No stow on the cluster; with `R` = the repo clone (in `$PROJECT`, not linked into `~`): `ln -sf $R/bash/.bashrc ~; ln -sfn $R/tmux/.config/tmux ~/.config/tmux` (Neovim: see HPC Neovim). |
| **tmux/**              | tmux config (`stow tmux`). With `DOTFILES_PROFILE=hpc` it skips `cursor-style` and `allow-passthrough` and sources `hpc.conf`: no Nerd icon, `screen-256color` fallback, slower status refresh. Needs tmux ≥ 3.3. |
| **ghostty/**           | [Ghostty](https://ghostty.org) config (`stow ghostty` → `~/.config/ghostty/config`). Oxocarbon theme; DMS-generated `themes/` stay untracked. |
