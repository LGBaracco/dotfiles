# Dotfiles

NixOS-based personal dotfiles.

## Layout

| Directory              | Description                                                                                                                                                                                     |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **nixos/**             | Main part of the repo: a flake-based, full NixOS configuration. Host-agnostic setup with two flakes for two hosts (`nixdesktop`, `nixlaptop`) that share common modules and home configuration. |
| **niri/**              | Config for [niri](https://github.com/YaLTeR/niri), my Wayland compositor of choice.                                                                                                             |
| **mango/**             | Config for [mango](https://github.com/mangowm/mango) (mangowc), a dwl-based Wayland compositor selectable alongside niri in the DMS greeter.                                                    |
| **noctalia/**          | [Noctalia](https://github.com/noctalia-dev/noctalia-shell) shell config used with niri.                                                                                                         |
| **DankMaterialShell/** | [DankMaterialShell](https://github.com/AvengeMedia/DankMaterialShell) shell config used with niri/mango.                                                                                        |
| **julia/**             | Simple Julia startup script enabling [Revise](https://github.com/timholy/Revise.jl) and [OhMyREPL](https://github.com/KristofferC/OhMyREPL.jl).                                                 |
| **[onedrive-sync/](onedrive-sync/README.md)** | Dotfiles to make OneDrive work seamlessly on Linux over WebDAV. Auth tokens are fetched from Firefox; `onedrive-download`/`onedrive-upload` (`.local/bin`) handle sync. See the [usage guide](onedrive-sync/README.md). |
| **neovim/**             | Stowable Neovim config (`stow neovim` → `~/.config/nvim`). `.config/nvim/pack.json` is the one list of plugins (name = nixpkgs pname, git `src`), treesitter parsers and tools (nixpkgs attr / mason package) for both install paths. NixOS: `module.nix` ([nix-wrapper-modules](https://github.com/BirdeeHub/nix-wrapper-modules)) builds the plugin pack and the PATH suffix from it; NixOS takes `neovim/.config/nvim` as the `nvim-config` input and installs via `getInstallModule`. `wrappers.neovim.liveLua` (default `true`) loads Lua from `~/.config/nvim` without rebuilds; set `liveLua = false` to bake the tree into the store. Without Nix (no `vim.g.nix_info_plugin_name`), `lua/config/pack.lua` installs the same plugins with `vim.pack` at the revisions in the committed `nvim-pack-lock.json`, and mason.nvim adds the tools (appended to PATH, so host binaries win). `:PackSync` aligns plugins to the lockfile and installs mason tools, parsers and blink.cmp's fuzzy binary; `:PackUpdate` updates plugins (commit the lockfile afterwards). Neither exists on Nix. `DOTFILES_PROFILE=hpc` drops the `desktopOnly` plugins/tools (LaTeX, noice/notify, cinnamon, neo-tree, precognition) and uses the curated parser list; Lua skips absent plugins via `config.has`. |
| **Neovim off Nix**      | Ubuntu and HPC (JSC). Needs Neovim ≥ 0.12 (official release tarball, e.g. under `~/.local` with `~/.local/bin/nvim` linked), `git`, `curl`, `tar`, `unzip`, `make` and a C compiler (parsers, LuaSnip jsregexp). Mason tools that need `npm`/`go`/`cargo`/`python3`/`luarocks`/`java` are skipped and reported when that toolchain is absent. Host-provided: `rg`, `fd`, ImageMagick, Julia, Quarto, `astyle`, `jsonfmt`, TeX + zathura + `wl-clipboard` (desktop), and the uv tools `ruff`, `ty`, `jupytext`, `debugpy`, `ipython` plus the Molten host `pynvim` (command in `lua/plugins/repl/quarto.lua`). Without a package manager (HPC), `neovim/scripts/nvim-deps-bundle` packs pinned static Quarto, `rg`, `fd` and `jsonfmt` into one `nvim-deps.tar.gz`; install with `tar -xzf nvim-deps.tar.gz -C ~/.local`. Bootstrap: `stow neovim` (Ubuntu) or, on the cluster with `R` = the repo clone in `$PROJECT`, `ln -sfn $R/neovim/.config/nvim ~/.config/nvim`; then `nvim --headless +PackSync +qa` (exit code 1 on failure, lists missing host tools). Where the `tree-sitter` CLI cannot run (release binaries need glibc ≥ 2.39; JURECA has 2.34) parsers are compiled with `cc` directly, skipping the few that need `tree-sitter generate` (`latex`). On JSC run it in an interactive shell on a login node (`.bashrc` sets `DOTFILES_PROFILE=hpc` there; compute nodes are offline), again after a pull that changes `pack.json` or the lockfile; a UI session reminds you. Plugins, mason and parsers live in `~/.local/share/nvim` (inside `$PROJECT` when `~/.local` is linked there). |
| **emacs/**             | My Doom Emacs configuration, setup for python, julia, and nix development.                                                                                                                      |
| **claude/**            | The whole `~/.claude` folder (`stow claude` → `~/.claude` symlink). `.gitignore` whitelists config only (settings, agents, hooks, themes, `skills/ask`); credentials, transcripts and caches stay local. Includes a read-only **Ask mode**: run `ask` (fish alias) for `claude --agent ask`, with Bash restricted by `hooks/ask-readonly-bash.py`; or `/ask <question>` mid-session. |
| **fish/**              | Fish config (`stow fish` → `~/.config/fish/config.fish`): aliases, Oxocarbon colors, zoxide + starship init. Sources Home Manager's `hm-session-vars.sh` via `babelfish` when present (NixOS), skipped elsewhere. |
| **starship/**          | [Starship](https://starship.rs) prompt (`stow starship` → `~/.config/starship.toml`): Oxocarbon powerline with OS icon, user, host, directory, git and language segments. |
| **fastfetch/**         | [Fastfetch](https://github.com/fastfetch-cli/fastfetch) config (`stow fastfetch` → `~/.config/fastfetch/config.jsonc`): no logo, boxed key/value columns, one color per section (system, desktop, hardware, miscellaneous). Layout notes are at the top of the file. |
| **bash/**              | Minimal, dependency-free `.bashrc` for HPC (JSC) hosts where bash is mandatory: mirrors `config.fish` aliases, falls back to `xterm-256color` when `$TERM` has no terminfo (e.g. `xterm-ghostty`), detects the host (`jr*`/`jw*`/`jusuf*` or `$SYSTEMNAME`; override with `DOTFILES_PROFILE`) and exports `DOTFILES_PROFILE`. Plain Oxocarbon `PS1` prompt; uses nvim if present, vim/vi otherwise. No stow on the cluster; with `R` = the repo clone (in `$PROJECT`, not linked into `~`): `ln -sf $R/bash/.bashrc ~; ln -sfn $R/tmux/.config/tmux ~/.config/tmux` (Neovim: see Neovim off Nix). |
| **tmux/**              | tmux config (`stow tmux`). With `DOTFILES_PROFILE=hpc` it skips `cursor-style` and `allow-passthrough` and sources `hpc.conf`: no Nerd icon, `screen-256color` fallback, slower status refresh. Needs tmux ≥ 3.3. |
| **ghostty/**           | [Ghostty](https://ghostty.org) config (`stow ghostty` → `~/.config/ghostty/config`). Oxocarbon theme; DMS-generated `themes/` stay untracked. |
| **keyring/**           | Ubuntu + niri only (`stow keyring` → `~/.local/share/applications`). Overrides of the snap `.desktop` files for Brave, VS Code and Obsidian that add `--password-store=gnome-libsecret`: Chromium/Electron only picks GNOME Keyring when `XDG_CURRENT_DESKTOP` names GNOME/Unity/etc., and under niri it silently falls back to an unencrypted store. Same fix as `withGnomeKeyring` in `nixos/.../apps/chromium.nix`. Brave (strict snap) also needs `sudo snap connect brave:password-manager-service`. Re-copy from `/var/lib/snapd/desktop/applications/` if a snap changes its launcher. |
